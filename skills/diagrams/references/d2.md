## Model and notation

```d2
direction: right
app: Application {
  host: Host
  game: Game module
}
ports: Environment ports
app.host -> ports: provides
app.game -> ports: depends on
```

- Nested objects express real containment; the key path (`app.host`) is the stable identity, the label is display text.
- Use explicit verbs on connections. Line style (`style.stroke-dash`) carries one meaning per diagram.
- Classes (`classes: {...}`) are styling metadata. They never rename domain concepts.

## Sequences, tables, and states

Sequence: `shape: sequence_diagram`; declaration order is lifeline order.

```d2
save: {
  shape: sequence_diagram
  session: Session
  storage: Storage
  session -> storage: write(snapshot)
  storage -> session: saved {style.stroke-dash: 3}
}
```

SQL tables: `shape: sql_table` with typed rows and constraints. Crow's Foot endpoints use `cf-one`, `cf-one-required`, `cf-many`, `cf-many-required`; a source endpoint needs a connection that has a source arrowhead (`<->`).

```d2
player: {
  shape: sql_table
  id: string {constraint: primary_key}
}
seat: {
  shape: sql_table
  player_id: string {constraint: foreign_key}
}
player.id <-> seat.player_id: occupies {
  source-arrowhead.shape: cf-one-required
  target-arrowhead.shape: cf-many
}
```

States: nodes for states, labelled connections for transitions, containers for nested states. Define the start/end and guard conventions in the legend. If the model needs history states, orthogonal regions, or entry/exit actions, use PlantUML for that view.

## Local compilation

```bash
d2 validate docs/diagrams/module-map.d2
d2 --layout=elk --theme=0 --pad=16 docs/diagrams/module-map.d2 docs/diagrams/module-map.light.svg
d2 --layout=elk --theme=200 --pad=16 docs/diagrams/module-map.d2 docs/diagrams/module-map.dark.svg
```

`--dark-theme` instead embeds both themes in one SVG that follows the viewer's color scheme. Use a fixed `--scale` when consumers need stable natural dimensions. Check the exit status even if a partial file exists.

Compact variant from the same source: prepend a presentation-only `direction: down` override (for example by piping the source with the override through the CLI from the source directory so relative imports still resolve). Never copy the nodes and edges into a second file.

## Consistent styling

Theme defaults vary between versions. When diagrams must match a design system, set connection and shape styles explicitly; shape globs do not style connections, so add the connection glob too:

```d2
**.style.font-size: 13
(*** -> ***)[*].style.font-size: 13
(*** -> ***)[*].style.stroke-width: 1
```

Map `font-color` and `stroke` to the design system's tokens in a shared imported file rather than in each diagram. Keep font metrics and the rendered font together: pin font files through the CLI flags instead of swapping fonts in the SVG after layout.

## Layout engines

| Engine | Use when |
|---|---|
| `dagre` | default layered layout for simple directed views |
| `elk` | directed views with many edges, and field-level SQL-table links |
| `tala` | architecture diagrams needing per-container direction and position hints (separately installed) |

Check engine-specific keywords against the installed version; not every keyword works with every engine.

## Limits

D2 is for software structure. It is not a charting or mapping tool. Arbitrary named ports, overlapping containment, and large interactive graph exploration need another notation or a dedicated viewer. When a host cannot render D2, compile SVG beside the `.d2` source and link both.
