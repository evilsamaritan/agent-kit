# Compiled Diagram Component

Use locally compiled SVG for a project whose selected format is D2, PlantUML, Graphviz, or pre-rendered Mermaid. Source and compiler stay in the project's build; the browser needs only the shell and `visualization-diagram.js`.

## Markup

```html
<figure class="viz-compiled" data-viz-diagram="d2"
  aria-labelledby="module-map-title" aria-describedby="module-map-description">
  <figcaption class="viz-compiled__caption" id="module-map-title">Module dependencies</figcaption>
  <div class="viz-compiled__output" data-viz-diagram-output>
    <img src="module-map.light.svg" width="720" height="260"
      data-viz-diagram-theme="light" alt="Host provides ports; the module depends on them." />
    <img src="module-map.dark.svg" width="720" height="260" hidden
      data-viz-diagram-theme="dark" alt="Host provides ports; the module depends on them." />
  </div>
  <p class="viz-compiled__description" id="module-map-description">
    Host provides environment ports; the domain module depends on those ports.
    <a data-viz-diagram-source href="module-map.d2">Editable source</a>
  </p>
</figure>
<script src="visualization-diagram.js"></script>
```

Set `data-viz-diagram` to `mermaid`, `d2`, `plantuml`, or `graphviz`. Dimensions come from the SVG's natural dimensions, not the example numbers. Both wide theme variants are required; the runtime follows the shell's explicit Light/Dark control and the system preference in Auto mode. Hide all variants except wide/light in initial markup so source and description remain useful without JavaScript.

The contract checker verifies labelled/described IDs, a linked source, theme/view pairs, SVG paths, alt text, and dimensions. It checks that local SVG and source files exist relative to the artifact. Embedded `data:image/svg+xml` variants are supported for single-file delivery; keep the editable source available separately.

## Compact variants and fit

Add `data-viz-diagram-view="compact"` to two more images, one per theme, compiled from the same source with a compact layout. Wide is the default when that attribute is absent. The runtime switches at `data-viz-compact-at` (default 720 pixels of container width). It never changes the underlying source or chooses another language.

When a compact diagram is still too dense, use a relationship or message list over the same model ([responsive-layout.md](responsive-layout.md)). Without compact variants, the wide pair remains available with labelled local horizontal scrolling. Fit is allowed only within the 18% overflow limit used by the browser graph adapter; choose a source label size that remains at least 11px after fitting. Vertical wheel and touch gestures continue the page.

Apply the shared line weight, label typography, and palette during compilation ([visual-system.md](visual-system.md#typography-and-spacing)). Page CSS cannot reach an SVG embedded through `img`; theme pairing alone does not normalize a compiler's default 2px strokes or italic labels.

The runtime switches image visibility, measures fit, and exposes a visible error if the selected asset cannot load. The description and source link remain present in every state. It does not compile source or require a network renderer.

## Themes

Compile light and dark with the shell palette and identical relationships. Category styling follows [visual-system.md](visual-system.md#diagram-palette); keep neutral diagrams neutral. Explicit colors in source can override compiler themes, so inspect both outputs. System-preference CSS inside an SVG alone does not follow the shell's manual theme selection; separate compiled variants do.

## Links and interaction

An SVG loaded through `img` preserves its drawing but not internal clickable links or tooltips. Put consequential links in the surrounding HTML. When internal SVG interaction is required, inline the trusted, locally generated SVG into one coordinate system and bind the project's controls; retain unique SVG IDs, accessible names, the source link, both themes, and the scroll contract. Do not inject arbitrary remote SVG into the page.

## Validation

Compile with the project's selected tool and fail on a nonzero exit status. Check the artifact with `check-shell-contract.mjs`, then inspect both themes and wide/half-width/mobile states. Matching filenames and valid SVG do not establish equivalent topology or readable geometry.

The gallery's D2 outputs are generated by `scripts/render-d2-preview.mjs` from the eight `assets/_preview-*.d2` sources and the shared palette: two themes × wide/compact = 32 SVGs. The script pins D2 0.9.0 with the ELK layout and refuses another version; `--check` detects drift. Source and compile commands for each language are in the `diagrams` skill.
