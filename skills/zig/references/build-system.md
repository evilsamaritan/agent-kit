## build.zig

One module carries the source, target, optimize mode, and link settings. The compile steps take the module.

```zig
const std = @import("std");

pub fn build(b: *std.Build) void {
    const target = b.standardTargetOptions(.{});
    const optimize = b.standardOptimizeOption(.{});

    const mod = b.createModule(.{
        .root_source_file = b.path("src/main.zig"),
        .target = target,
        .optimize = optimize,
        .link_libc = true,
    });
    mod.linkSystemLibrary("sqlite3", .{});

    const exe = b.addExecutable(.{ .name = "myapp", .root_module = mod });
    b.installArtifact(exe);

    const tests = b.addTest(.{ .root_module = mod });
    const run_tests = b.addRunArtifact(tests);
    const test_step = b.step("test", "Run unit tests");
    test_step.dependOn(&run_tests.step);
}
```

Split a library module from the executable module when other code imports it (`mod.addImport("name", other)`), so tests build the library without `main`.

## build.zig.zon and dependencies

```zig
.{
    .name = .myproject,        // enum literal, not a string
    .version = "0.1.0",
    .fingerprint = 0x0,        // generated by `zig init`; never hand-write or copy another package's
    .minimum_zig_version = "0.17.0",
    .dependencies = .{},
    .paths = .{ "build.zig", "build.zig.zon", "src" },
}
```

Add a dependency with `zig fetch --save <url>`; it writes the URL and hash. Use it in the build:

```zig
const dep = b.dependency("name", .{ .target = target, .optimize = optimize });
mod.addImport("name", dep.module("name"));
```

Then `@import("name")` in source. A dependency's module name is whatever its `build.zig` exports.

## C translation by version

Pick by the project's Zig version.

| Version | How a C header becomes a Zig import |
|---------|--------------------------------------|
| 0.15 and earlier | `const c = @cImport({ @cInclude("sqlite3.h"); });` in source |
| 0.16 | `@cImport` still works but is deprecated; use the build-system translate step |
| 0.17 and later | `@cImport` is removed; use the translate-c package as a build dependency |

0.16 build step:

```zig
const translate_c = b.addTranslateC(.{
    .root_source_file = b.path("src/c.h"),
    .target = target,
    .optimize = optimize,
});
mod.addImport("c", translate_c.createModule());
```

0.17 package. The repository's `main` branch tracks Zig master (its `minimum_zig_version` is a 0.18 development build), so fetch the branch for the project's toolchain, `zig-0.17.x` (a `zig-0.16.x` branch exists for 0.16):

```
zig fetch --save git+https://codeberg.org/ziglang/translate-c#zig-0.17.x
```

Then in `build.zig`:

```zig
const Translator = @import("translate_c").Translator;

const translate_c = b.dependency("translate_c", .{});
const translator: Translator = .init(translate_c, .{
    .c_source_file = b.path("src/c.h"),
    .target = target,
    .optimize = optimize,
    .link_system_libs = &.{.{ .name = "sqlite3" }},
});
mod.addImport("c", translator.mod);
```

Either way, source then does `const c = @import("c");`. Keep `src/c.h` to the includes the project needs. The package's README lists further options (static functions, function bodies, flexible arrays) and the `translator.output_file` alternative to a module.

## Linking C libraries

```zig
mod.linkSystemLibrary("sqlite3", .{}); // system library found via pkg-config or the search path
// .link_libc = true in createModule when any C code or libc call is used
```

Compile vendored C sources into the module with `mod.addCSourceFiles(...)` and add include paths with `mod.addIncludePath(b.path("vendor/include"))`.

## Cross-compiling

The target is an option, not a setup step: `zig build -Dtarget=aarch64-linux-musl`, `-Dtarget=x86_64-windows-gnu`, `-Dtarget=wasm32-wasi`. Combine with `-Doptimize=ReleaseSafe`. C dependencies cross-compile with the bundled libc headers; system libraries from the host do not, so vendor or fetch them for cross builds.
